# 04 — Embedding mplib

Everything in §1–§5 was verified by building and running
`reference/host_shim_reference.c` against the real sources. Where a statement
says **CONTRACT**, getting it wrong crashes or silently corrupts.

## 1. The public API

`mplib.h` (generated by `ctangle mp.w`) is the whole surface. A cleaned copy is
in `reference/mplib-public-api.h`. The parts that matter:

```c
typedef struct MP_instance *MP;

MP_options *mp_options(void);          /* zeroed options block, caller fills  */
MP          mp_initialize(MP_options*);/* NULL on failure                      */
int         mp_execute(MP, char *s, size_t l);   /* run one complete program   */
int         mp_finish(MP);             /* cleanup + free; returns history      */
int         mp_status(MP);
mp_run_data*mp_rundata(MP);            /* the in-memory streams + figures      */
void        mp_set_internal(MP, char *n, char *v, int isstring);
char       *mp_metapost_version(void);

/* value extraction, useful for a host API */
double  mp_get_numeric_value(MP, const char *s, size_t l);
int     mp_get_boolean_value(MP, const char *s, size_t l);

mp_knot mp_get_path_value   (MP, const char *s, size_t l);
```

## 2. Options that must be set

```c
MP_options *o = mp_options();
o->noninteractive   = 1;                 /* CONTRACT: enables in-memory streams */
o->interaction      = mp_nonstop_mode;
o->extensions       = 1;                 /* CONTRACT: routes btex to make_text  */
o->math_mode        = mp_math_scaled_mode;   /* or double / decimal             */
o->mem_name         = xstrdup("plain");  /* CONTRACT: NULL here → NULL deref    */
o->job_name         = xstrdup("job");
o->random_seed      = 42;                /* CONTRACT for determinism            */
o->halt_on_error    = 0;
o->ini_version      = 0;
o->find_file        = mpwasm_find_file;
/* open/read/write/close/eof/flush are set but IGNORED — see §3 */
o->make_text        = mpwasm_make_text;
o->run_script       = mpwasm_run_script;
o->run_make_mpx     = mpwasm_run_make_mpx;   /* classic path, see docs/05 §7   */
o->run_editor       = mpwasm_run_editor;     /* must be a no-op                */
o->banner           = "MetaPost-WASM";
```

**`mem_name` is not optional.** With `mem_name == NULL`, `mp_execute` reaches
`mp_open_mem_file`, finds nothing, and passes `NULL` to `wterm()`. Observed as a
segfault during scoping. Set it to `"plain"` (loads `plain.mp`) or `"mpost"`
(loads `mpost.mp`, which in turn inputs `plain.mp` — this is what the `mpost`
CLI does).

**`extensions = 1` changes `btex` semantics.** With `extensions = 0` (the
default) `btex ... etex` goes down the classic `.mpx` road via
`run_make_mpx`, and — crucially — **fails outright when the source came from a
string rather than a file**, because `mp_t_next` refuses with "we are not
reading a file". With `extensions = 1`, `btex`, `verbatimtex` and `maketext`
all call `make_text` instead. Since `mp_execute` feeds a string, we need
`extensions = 1`. This is the same mode LuaTeX/ConTeXt use.

## 2b. CONTRACT: `mp_execute` reads exactly ONE line

**This determines the shape of the whole driver.** `mp_execute(mp, s, l)` copies
`s` into `run_data.term_in`, then calls `mp_input_ln` **once**, terminates the
buffer with `%`, and enters `do { mp_do_statement } while (cur_cmd() != mp_stop)`.

When the scanner reaches the end of that one line and asks for more terminal
input, `mp.w` line ~19041 does this:

```c
if (mp->interaction > mp_nonstop_mode) { ...prompt the user... }
else mp_fatal_error (mp, "*** (job aborted, no legal end found)");
```

There is no path that reads a second line from the string. Verified: a
two-line source string fails with `! Emergency stop.` and `history = 3`, with
or without a trailing newline; the identical source on one line succeeds.

### The driver pattern

Write the document to the VFS and pull it in with a one-line `input`:

```c
/* JS side: FS.writeFile('/work/job.mp', source) */
mp_execute (mp, "input job", 9);
```

Verified: a six-line document with comments, two `beginfig` blocks and a
`label` compiles to two figures this way; and a `btex $x^2$ etex` inside the
file still reaches our `make_text` callback under `extensions = 1`.

Do **not** try to flatten the source onto one line. MetaPost's `%` comments run
to end of line, `btex ... etex` has line-sensitive whitespace rules governed by
`texscriptmode`, and error messages would all report line 1.

Three consequences worth noting:

* The user's source lives in a real VFS file, so `mp_start_input`'s
  `in_name`/`in_area`/`in_ext` are populated — which means the **classic
  `.mpx` path (`extensions = 0`) also works**, not just the `make_text` route.
  See `docs/05` §7.
* Diagnostics get real file names and line numbers for free.
* `jobName` should match the file name so `outputtemplate`'s `%j` behaves.

## 3. Non-interactive mode overrides your I/O callbacks

**CONTRACT.** When `noninteractive` is set, `mp_initialize` replaces
`open_file`, `close_file`, `eof_file`, `flush_file`, `read_ascii_file`,
`write_ascii_file`, `read_binary_file`, `write_binary_file` and
`shipout_backend` with its own `mplib_*` implementations. Whatever you put in
`MP_options` for those is discarded.

What survives: **`find_file`**, `make_text`, `run_script`, `run_make_mpx`,
`run_editor`.

The replacement `mplib_open_file` does this:

| `ftype` | Behaviour |
| --- | --- |
| `mp_filetype_terminal` (r) | reads from `run_data.term_in` (the string you passed to `mp_execute`) |
| `mp_filetype_terminal` (w) | resets and writes to `run_data.term_out` |
| `mp_filetype_error` | `run_data.error_out` |
| `mp_filetype_log` | `run_data.log_out` |
| `mp_filetype_postscript` / `_bitmap` | **frees** the previous `run_data.ship_out` and writes to a fresh one |
| everything else | `find_file(fname, mode, ftype)` → `fopen(result, "<mode>b")` |

So the shape of the world is: **`find_file` is our kpathsea; the Emscripten
filesystem supplies the bytes.** That is a good deal — we get `fopen`/`fread`
semantics for free and can use MEMFS in the browser and NODEFS in the CLI.

Do **not** set `print_found_names` or `file_line_error_style` just to get
`find_file` called: it is already called on every open, and those flags make it
fire twice.

## 4. The `find_file` contract

```c
char *find_file(MP mp, const char *fname, const char *fmode, int ftype);
```

* Return a **`malloc`ed** absolute path, or `NULL` if not found.
* For `fmode[0] != 'r'` (writing) return a path even if nothing exists there.
* **Handle already-absolute paths.** Some call sites pass a path that a previous
  `find_file` already resolved. Probe `fname` itself before searching. (Observed
  during scoping: without this, `plain.mp` resolved, then failed on the second
  lookup.)
* `ftype` is the `enum mp_filetype`: `program`(2) for `.mp`, `log`,
  `postscript`, `bitmap`, `memfile`, `metrics`(TFM), `fontmap`(8),
  `font`(`.pfb`), `encoding`, `text`.

Call sites, exhaustively (`grep 'mp->find_file)' mp.w psout.w`):

1. `mp_do_open_file` — only when `print_found_names || file_line_error_style`.
2. `mp_open_mem_name` — the preload file.
3. `mplib_open_file` — **every** non-stream open in non-interactive mode.
4. `psout.w`'s `mp_init_map_file` — looks for `mpost.map`, `ftype = fontmap`.

Note #4: MetaPost asks for **`mpost.map`**, not `psfonts.map`. Ship a
`mpost.map` in the bundle (upstream TeX Live's `mpost.map` is a thin wrapper
that includes the CM/psfonts entries). If it is missing MetaPost continues
silently and later fails to embed fonts.

## 5. The other callbacks

### 5.1 `make_text` — the btex hook

```c
char *make_text(MP mp, const char *str, size_t len, int mode);
```

* `str`/`len` is the *body* of the block, whitespace-trimmed according to the
  `texscriptmode` internal.
* `mode` is the **verbatim flag**: `1` for `verbatimtex ... etex`, `0` for
  `btex ... etex` and for the `maketext "..."` primitive.
* The return value is **MetaPost source text**, which mplib pushes into the
  input stream as a one-line pseudo-file and then scans in place of the block.
  It must therefore parse as a *primary expression* in the context where `btex`
  appeared.
* Return a `malloc`ed string; mplib `free`s it.
* For `mode == 1` (verbatimtex) return `""` — the TeX preamble contributes no
  MetaPost tokens.
* For a cache miss return `"nullpicture"` and record the miss.

Verified: returning `image(draw unitsquare xscaled 20 yscaled 8;)` from
`make_text` produced a correctly placed box inside `label.top(btex Hello etex,
(0,50))`.

### 5.2 `run_script` — the JavaScript hook

```c
char *run_script(MP mp, const char *str, size_t len);
```

Same protocol: the returned string is injected as MetaPost source. This is the
`runscript "..."` primitive. Wire it to a user-supplied JS function; **off by
default** (`docs/10` §3). A `runscript` that returns `"\"hello\""` makes
`runscript "..."` evaluate to the MetaPost string `"hello"`.

### 5.3 `run_make_mpx`

```c
int run_make_mpx(MP mp, char *origname, char *mpxname);
```

Only reached with `extensions = 0`. Return non-zero for success. Our
implementation just verifies that `mpxname` exists in the VFS, because the JS
layer pre-generates it (`docs/05` §7).

### 5.4 `run_editor`

Must exist and do nothing. Never wire it to anything.

### 6.1 Rendering a figure — the drain rule

**CONTRACT.** `mp_svg_ship_out` / `mp_ps_ship_out` write into
`run_data.ship_out`, and *opening a new output frees the previous stream*.
So:

```c
const char *mpwasm_figure_svg(mpwasm_ctx *c, int i, int prologues) {
  mp_edge_object *e = nth_edge(c, i);
  mp_svg_ship_out(e, prologues);              /* writes run_data.ship_out */
  mp_run_data *rd = mp_rundata(c->mp);
  return copy_out(rd->ship_out.data, rd->ship_out.used);  /* copy NOW */
}
```

Never render two figures and then read the buffer — you will get only the
second. Verified during scoping.

Signatures (from the generated headers):

```c
int mp_svg_ship_out   (mp_edge_object *hh, int prologues);
int mp_svg_gr_ship_out(mp_edge_object *hh, int prologues, int standalone);
int mp_ps_ship_out    (mp_edge_object *hh, int prologues, int procset);
int mp_gr_ship_out    (mp_edge_object *hh, int prologues, int procset, int standalone);
```

## 7. Determinism

Two runs of the same source must be byte-identical — the TeX Bridge's fixpoint
loop depends on it, and users will diff the output.

1. `o->random_seed = <fixed>`. Otherwise MetaPost seeds from `time` + `day`.
2. Freeze the date. `mp_execute` calls `mp_fix_date_and_time()` internally, so
   setting internals before the run is not enough: **prepend** to the source
   ```
   year:=2026; month:=1; day:=1; time:=0;
   ```
   when `options.deterministic` is on (the default). These are ordinary
   writable internals.
3. Do not let `mpwasm` emit a wall-clock creation date into SVG/PS headers —
   MetaPost writes `%%CreationDate` from those internals, so (2) covers it.
4. In `tex.wasm`, set `FORCE_SOURCE_DATE=1` / `SOURCE_DATE_EPOCH` so
   `\year\month\day\time` and the DVI preamble comment are fixed.

## 8. Memory and lifetime rules

* One `MP` per compilation. `mp_execute` terminates the job; a second call on
  the same instance returns immediately with the stored history.
* `mp_finish` frees everything including the `edges` list. **Copy every figure
  out before calling it.**
* `mp_rundata(mp)->edges` is owned by mplib. Do not `mp_gr_toss_objects` it
  yourself in non-interactive mode.
* Strings returned by `mp_get_string_value` are `malloc`ed and yours to free.
* The `xmalloc` family in `mpwasm_host.c` must abort on OOM, not return NULL —
  the vendored code does not check. Abort maps to a wasm trap, which the worker
  turns into a clean error.
