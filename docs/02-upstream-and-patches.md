# 02 — Upstream sources, pinning, and the patch set

## 1. What to vendor

| Component | Source | Pin |
| --- | --- | --- |
| MetaPost (`mplibdir`) | TeX Live `texk/web2c/mplibdir` | A released TeX Live source tarball, **not** master |
| pdfTeX + web2c + kpathsea | TeX Live `texk/web2c`, `texk/kpathsea` | same tarball |
| CWEB (`ctangle`) | TeX Live `texk/web2c/cwebdir` or CTAN `cweb` | same |
| decNumber | already inside `mplibdir` (`decNumber.c`, `decContext.c`) | — |
| texmf files | TeX Live `texmf-dist` | same release |

### 1.1 Pin to a release, and say which one

Scoping was done against **TeX Live master (MetaPost 3.00-dev)** because that
is what GitHub's mirror serves. The locally installed oracle was **TeX Live
2025 / MetaPost 2.11**. These differ. Before writing any code:

```sh
curl -O https://ftp.tug.org/texlive/historic/2025/texlive-20250308-source.tar.xz
```

and pin to it. Record the exact tarball name and SHA-256 in
`vendor/SOURCES.lock`. Every golden file in the test suite is only meaningful
relative to that pin.

**Verify on arrival** (the scoping notes were taken against master):

1. `mp_execute()` still ends with `mp_final_cleanup()` — i.e. one call per job.
2. `MP_options` still has `extensions`, `make_text`, `run_script`.
   `extensions` and `make_text` are relatively recent; if the 2025 tarball
   lacks them, either move the pin forward to a release that has them or fall
   back to the classic `run_make_mpx` route (`docs/05` §7), which exists in
   every version.
3. `mpx_run_dvitomp()` is still exported from `mpxout.h`.

A 30-line script under `scripts/verify-pin.sh` should assert all three by
grepping the tangled headers, and run in CI.

### 1.2 Getting just what you need

The full TeX Live source tarball is ~600 MB. Use a sparse extraction:

```
texk/web2c/mplibdir/          # MetaPost
texk/web2c/*.{w,ch,h,c}       # tex.web glue, texmfmp.c, web2c drivers
texk/web2c/web2c/             # the web2c translator (built natively)
texk/web2c/cwebdir/           # ctangle (built natively)
texk/web2c/pdftexdir/         # pdfTeX
texk/kpathsea/                # path searching for tex.wasm only
libs/zlib/ libs/libpng/       # pdfTeX deps
libs/xpdf/                    # pdfTeX image inclusion (stub-able, see §5.2)
texk/web2c/triptrap/          # mptrap conformance data
```

Vendor as a git submodule pointing at `TeX-Live/texlive-source` at the tagged
commit for that release, plus a `scripts/extract-vendor.sh` that copies the
above subtree into `vendor/`. Do not commit 600 MB.

## 2. Tangling: CWEB, not web2c

MetaPost has been CWEB since 1.0 — `ctangle` produces C directly. **No Pascal,
no web2c, no `tangle` for MetaPost.** Verified: `ctangle mp.w` on a clean
checkout, with no other files present, produces `mp.c`, `mplib.h`, `mpmp.h`
and exits 0.

| Input | Outputs |
| --- | --- |
| `mp.w` | `mp.c`, `mplib.h` (public API), `mpmp.h` (internal) |
| `psout.w` | `psout.c`, `mplibps.h` (graphic object structs!), `mppsout.h` |
| `svgout.w` | `svgout.c`, `mplibsvg.h`, `mpsvgout.h` |
| `tfmin.w` | `tfmin.c`, `tfmin.h` |
| `mpxout.w` | `mpxout.c`, `mpxout.h` |
| `mpmath*.w` | `mpmath*.c`, `mpmath*.h` |
| `mpstrings.w` | `mpstrings.c`, `mpstrings.h` |
| `mpost.w` | `mpost.c` — the kpathsea CLI driver. **We do not use it.** Read it as documentation of how upstream wires the callbacks, then write our own. |

Build `ctangle` natively as part of the build (it is three small C files).
Cache the tangled `.c`/`.h` in `build/gen/` keyed on the source hash.

`tex.wasm` *does* need the Pascal path: `tangle` (from `web`/`tangle.web`,
bootstrapped from the shipped `tangle.c`… or more simply, TeX Live's build
system) and `web2c`. See `docs/03` §4.

## 3. The compatibility shim — `w2c/config.h`

Every `mplibdir` source does `#include <w2c/config.h>`, which in a real TeX Live
build is generated by autoconf and drags in kpathsea's `lib.h`. We replace it
with a ~35-line header. **This was written and verified during scoping**; it is
in `reference/w2c-config-shim.h`. It must provide:

* `typedef int integer; typedef int64_t integer64;` and `boolean` guarded by
  `HAVE_BOOLEAN`;
* the standard headers the sources assume are already pulled in: `stdio.h`,
  `stdlib.h`, `string.h`, `assert.h`, `float.h`, `math.h`, `unistd.h`,
  `errno.h`, `sys/stat.h`, `dirent.h`, `time.h`;
* feature macros `HAVE_SYS_STAT_H`, `HAVE_UNISTD_H`, `HAVE_ACCESS`,
  `HAVE_MKSTEMP`, `HAVE_DIRENT_H`;
* declarations for kpathsea's allocators — `xmalloc`, `xrealloc`, `xcalloc`,
  `xstrdup`, `concatn` — which **we implement** in `mpwasm_host.c`;
* `FATAL1(fmt,a)` / `FATAL(fmt)` macros.

Do not `#define` the optional-library version symbols: `mp.w` declares them
`extern` (`extern const char *COMPILED_CAIRO_VERSION_STRING;` etc.) so macros
produce a syntax error. Define them as real objects in C. See §4.

## 4. Stubbing what we do not link

`mp.c` references four families of symbols from libraries we do not build.
All four are contained and safe to stub. This list is exhaustive and was
obtained by linking and reading the undefined symbols.

### 4.1 Version reporting

`mp_show_library_versions()` needs:

```c
const char *COMPILED_CAIRO_VERSION_STRING  = "none";
const char *COMPILED_PIXMAN_VERSION_STRING = "none";
const char *COMPILED_MPFR_VERSION_STRING   = "none";
const char *COMPILED_MPFI_VERSION_STRING   = "none";
const char *const COMPILED_gmp_version     = "none";
int COMPILED__GNU_MP_VERSION = 0, COMPILED__GNU_MP_VERSION_MINOR = 0,
    COMPILED__GNU_MP_VERSION_PATCHLEVEL = 0;
const char *cairo_version_string(void)  { return "none"; }
const char *pixman_version_string(void) { return "none"; }
const char *mpfr_get_version(void)      { return "none"; }
const char *mpfi_get_version(void)      { return "none"; }
```

`mp.w` also `#include`s `<zlib.h>` and `<png.h>` purely for `ZLIB_VERSION`,
`zlibVersion()`, `PNG_LIBPNG_VER_STRING` and `png_libpng_ver`. Supply two
four-line stub headers on the include path rather than patching `mp.w`.

### 4.2 MPFR/MPFI number systems (phase 1–3)

```c
void *mp_initialize_binary_math(MP mp)   { return NULL; }
void *mp_initialize_interval_math(MP mp) { return NULL; }
```

Returning `NULL` makes `math_mode = binary|interval` fail at initialisation.
**Patch requirement:** `mp_initialize` does not check for `NULL` here. Either
(a) validate `math_mode` in our own C entry point and reject those modes with a
clean error before calling `mp_initialize`, or (b) add a two-line null check.
Prefer (a) — no upstream patch.

### 4.3 Cairo/PNG backend

```c
void mp_png_backend_initialize(MP mp) {}
void mp_png_backend_free(MP mp) {}
int  mp_png_gr_ship_out(void *hh, const char *opts, int standalone) { return 1; }
```

`outputformat:="png"` then fails cleanly. Intercept it earlier in the JS layer
and either refuse with a good message or rasterise the SVG (`docs/07` §6).

### 4.4 Never linked at all

`lmplib.c` (the Lua binding) and `mpost.c` (the kpathsea CLI). Do not compile
them.

## 5. The patch set

Keep every patch in `patches/NNNN-name.patch`, applied by
`scripts/apply-patches.sh`, each with a header comment giving *rationale* and
*what would break upstream if it were merged*.

### 5.1 `0001-mpxout-expose-mpto.patch` (required)

`mpx_mpto()` — the function that turns a `.mp` file into a `.tex` file with
`\mpxshipout` wrappers — is `static`. We need it callable without going
through `mpx_makempx()`, which insists on also running TeX and `dvitomp`.

Add to `mpxout.w`, in the `@<Makempx header information@>` section:

```c
typedef struct mpx_mpto_options {
  int   mode;          /* mpx_tex_mode */
  char *mpname;        /* input .mp path */
  char *texname;       /* output .tex path */
  char *mptexpre;      /* usually "mptexpre.tex" */
  int   debug;
} mpx_mpto_options;
int mpx_run_mpto (mpx_mpto_options *opt);
```

implemented as a ~25-line wrapper that allocates an `MPX`, installs the jump
buffer, calls the existing `mpx_mpto`, and returns `mpx->history`.

*Alternative if you want zero patches:* call `mpx_makempx()` with `cmd == NULL`,
which runs `mpto` and then `goto DONE`. The problem is that `DONE` skips
`mpx_erasetmp`, the `.tex` filename is an internal `mkstemp` name you cannot
predict, and nothing hands it back. Patching is cleaner. A third option — port
`mpto`'s ~250 lines of lexing to TypeScript — is tempting for the scanner
anyway (`docs/05` §3) but **must not** replace the C version for the
authoritative extraction; keep the C as the oracle.

### 5.2 `0002-pdftex-dvi-only.patch` (required for M4/M6)

pdfTeX links `libs/xpdf` (C++, for `\pdfximage`) and libpng. In DVI mode none of
it runs. Options, in order of preference:

1. Build them — emscripten ports cover zlib and libpng
   (`-sUSE_ZLIB=1 -sUSE_LIBPNG=1`); xpdf compiles as C++ with `-fno-exceptions`
   off. Largest but zero-risk, and keeps `pdfoutput=1` available for free.
2. Stub the image-inclusion entry points and error at runtime if `\pdfximage`
   is used. ~200 lines of stubs; saves ~800 KB.

Decide at M4 on measured size. Start with (1); it is the path that keeps the
engine honest.

### 5.3 `0003-mp-restrict-shell.patch` (required)

`mp.w`'s `mp_run_script` default and the `run_editor` option are the only
escape hatches. We never install a shell-executing version, so this patch is
belt-and-braces: compile-time `#error` if anything tries to introduce
`system()`/`popen()` into `mplib.wasm`. Implement as a link-time check in CI
(`nm` the objects, fail on `system`, `popen`, `execvp`, `fork`) rather than a
source patch — cheaper and catches regressions in vendored code too.

`mpxout.c` **does** contain `do_spawn`/`execvp`. We compile `mpxout.c` for
`mpto`/`dvitomp` only; those code paths are in `mpx_makempx`, which we never
call. Either `#ifdef` them out with `0004-mpxout-no-spawn.patch` or accept that
`execvp` is unresolvable under wasi/emscripten and let the linker's
`-sERROR_ON_UNDEFINED_SYMBOLS=0` handle it — **no**: be explicit, patch them
out. An unresolved symbol that traps at runtime is a worse failure mode than a
compile error.

### 5.4 Patches that are NOT needed

For the record, so nobody goes looking:

* No patch is needed to remove kpathsea from mplib — it never had it.
* No patch is needed to make `btex` work through a callback — `extensions=1`
  is a supported upstream option.
* No patch is needed for the SVG glyph outlines — `prologues:=3` is upstream
  behaviour.
* No patch is needed to collect figures in memory — non-interactive mode does
  it by default.
